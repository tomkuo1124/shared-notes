SIO2487801

[26C2][TekkenOC][NVL-S] Memory Lighting 於 Modern Standby 期間持續亮著

分析日期：2026-08-13 · 分析基準：HPOMENBG log + System EVTX + Sleep Study Report

1問題摘要

Kingston Fury DDR5 記憶體的 RGB LED 在系統進入 Modern Standby (MS) 後持續亮著。測試涵蓋 4 個場景（IPF SMBUS Device Enabled/Disabled × 手動進入/Idle Timeout 進入），全部失敗。

Log 分析顯示：OGH 應用程式在 4 個場景中的 3 個，於 MS 進入前成功發送了 SetLightingOffAsync WMI 命令，軟體層回報「All done」完成。第 4 個場景（SMBUS Disabled + 手動進入）因系統剛重開、OGH 尚未啟動而未發送命令。然而，即使軟體層回報成功，記憶體 LED 在 MS 期間仍持續亮著。

BIOS 回報 supportLightingValue = 0，表示不支援 Memory LED lighting bypass control。BIOS 規格書中未定義 MS 期間記憶體 LED 的行為。故障層邊界位於 OGH 應用程式與 BIOS/EC 之間：WMI 命令被接受但未轉換為實際硬體操作。

2問題歸屬判定

Issue Owner：BIOS/EC Team   Highly Likely

依據：證據 ①②⑤ 顯示 OGH 正確發送 SetLightingOffAsync 並回報完成，但 LED 未實際關閉。證據 ③ 顯示 BIOS 不支援 Memory LED bypass control（supportLightingValue = 0）。BIOS 規格書（HP_OMEN_Spec_v0e.md）未定義 MS 期間記憶體 LED 行為。IPF SMBUS Device Enabled/Disabled 均無效（證據 ①② vs ⑤）。

變更歸屬的條件：若 BIOS 團隊能證明 WMI 命令確實透過 SMBUS 傳送到 Kingston Fury DIMM 的 LED 控制器，且控制器回傳 ACK 但仍不關燈，則歸屬應改為 Kingston（記憶體模組韌體）。

白話說明：OGH 在進入睡眠前呼叫了「關燈」指令，BIOS 也回覆「收到了」，但記憶體上的 LED 根本沒有反應。就像你按了遙控器的關燈鍵，電視顯示「已關燈」，但燈泡實際上還亮著。問題出在遙控器（OGH）和燈泡（DIMM LED）之間的接收器（BIOS/EC）。

已排除的假說

假說：OGH 沒有發送 SetLightingOff 命令 — 排除原因：Log 確認 3/4 場景已成功發送（證據 ①②⑤，行號 14947、16333、20828）

假說：IPF SMBUS Device 設定導致問題 — 排除原因：Enabled 和 Disabled 均失敗，設定無差異性

假說：OGH Process 異常崩潰 — 排除原因：僅場景 b-1 無 OGH 運行，原因是系統重開以切換 BIOS 設定（EVTX BootId 26→27），非 process crash

反證檢驗摘要

驗證項目預期實際結果結論
若 BIOS 正確處理 SetLightingOff LED 應關閉 LED 未關閉 BIOS 未正確執行
若問題在 OGH 未發送命令 至少 1 個有命令的場景應成功 3 個有命令的場景全部失敗 OGH 不是根因
BIOS 是否宣告支援此功能 supportLightingValue = 1 supportLightingValue = 0 BIOS 未宣告支援
SMBUS 設定是否為區分變數 Enabled/Disabled 結果不同 結果完全相同 SMBUS 設定非關鍵因素

BIOS 規格書缺口

HP_OMEN_Spec_v0e.md 中未定義以下內容：(1) Modern Standby 期間記憶體 LED 行為 (2) IPF SMBUS Device 設定 (3) 26C2 / TekkenOC / NVL-S 平台。「Memory LED lighting bypass control」旗標（Command 20009h 01h Bit 4）存在但行為語義未定義。

7其他觀察項目

DirectedDripsTransitionCount = 0

所有 5 個 MS session 的 Directed DRIPS 轉換次數均為 0，表示 SoC 從未進入最深層 S0ix 狀態。主要 offender 為 NCSI（網路狀態檢查）和 PCIe Root Ports。SW DRIPS 89~96%。

OGH Process 重啟模式

HPOMENBG 在每次 MS 喚醒後被殺掉並重新啟動新 PID（14564→18000→5528→11956）。重啟期間存在 10~15 秒的空窗期，此時無實體可控制 LED。

IsUserLock 行為差異

IsUserLock=True 時（手動鎖定後），Resume 路徑跳過 PBT_APMRESUMEAUTOMATIC 的 lighting reset，改由 Monitor ON 事件觸發。不影響根因但增加時序複雜度。

8Issue Owner 處理指南

BIOS/EC Team
  • 檢查 BIOS WMI Command 20009h 01h Bit 4（Memory LED lighting bypass control）為何回報 0 — 確認此平台（26C2/TekkenOC/NVL-S）是否應支援此功能
    參考：HPOMENBG log 行 234, 12773, 19177
  • 驗證 Command 20009h 09h（Set LED Animation for HyperX Memory）在 MS 進入時是否真正透過 SMBUS 將命令傳送到 Kingston Fury DDR5 DIMM 的 SPD5 Hub LED 控制器
    參考：HP_OMEN_Spec_v0e.md Command 20009h 09h/0Ah
  • 評估是否需要在 BIOS/EC 層級實作獨立的 MS 進入時記憶體 LED 關閉機制，不依賴 OGH userspace 應用程式（OGH 可能因重開機、crash 或時序問題而缺席）
    參考：證據 ④，PID 5528 空窗期 15 分 27 秒
  • 確認 IPF SMBUS Device 設定對記憶體 LED 控制路徑的預期行為 — 目前 Enabled/Disabled 結果完全相同，顯示此設定未影響 LED 控制鏈
    參考：場景 a vs b 比較
  • 更新 HP_OMEN_Spec 加入 26C2/TekkenOC/NVL-S 平台的 MS 期間記憶體 LED 行為定義，包含 supportLightingValue 旗標的預期值和行為語義
    參考：BIOS 規格書缺口分析
  • 調查 SMBUS Disabled 時溫度感測器回傳負值的問題（可能為獨立 bug）
    參考：證據 ⑥，行 20990~21100

9結論與建議

  • 根因方向：BIOS 接收了 OGH 的 SetLightingOff WMI 命令但未將其轉換為 SMBUS 硬體操作。BIOS 明確回報不支援 Memory LED bypass control（supportLightingValue = 0），且規格書中缺乏 MS 期間 LED 行為的定義。
  • 修復建議：BIOS 應實作 Command 20009h 的 SMBUS 轉發邏輯，確保 SetLightingOff WMI 命令能實際到達 Kingston Fury DIMM 的 LED 控制器。或在 EC 層級加入 MS 進入時的自動關燈機制。
  • 驗證方式：修復後，重新執行相同的 4 個測試場景（SMBUS Enabled/Disabled × Manual/Idle），確認 MS 期間 LED 確實關閉。可額外使用 SMBUS analyzer 確認 BIOS 是否真正發出 I2C 命令到 DIMM slave address。
  • 架構建議：長期應在 BIOS/EC 層加入不依賴 OGH 的記憶體 LED 關閉機制（類似 heartbeat timeout 後 EC 接管 thermal 的設計），以覆蓋 OGH 重啟空窗期和異常退出的場景。
